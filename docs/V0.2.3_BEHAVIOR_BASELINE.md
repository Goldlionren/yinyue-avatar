# yinyue-avatar v0.2.3 behavior baseline

This document freezes the behavior observed in production on 2026-07-28. The
production workflow is authoritative. v0.2.4 and later must retain these
contracts unless a documented, tested migration explicitly supersedes one.

## CLI and process contract

`bin/avatarctl` invokes `python3 lib/avatarctl.py`. Successful commands write one
JSON object to stdout and exit 0. Expected validation or business errors use
stderr prefixed with `ERROR:` and exit 2. Unexpected exceptions print a
traceback and exit 3.

| Command | Arguments | Effect |
|---|---|---|
| `context` | none | Returns `persona`, current `state`, rendered `status_text`, and up to five recent history events. May initialize a missing runtime. |
| `status` | none | Returns current state. May initialize a missing runtime. |
| `history` | `--last N` | Returns the last N JSONL events. |
| `update` | repeated `--set path=value`, optional `--remember` | Applies only configured allowlisted fields, increments `continuity.revision`, atomically writes state, then appends history. |
| `show` | `--say`, `--channel`, `--no-send`, `--foreground` | Queues or foreground-runs generation from current state. |
| `render` | repeated `--set`, `--remember`, plus show options | Builds a candidate with a minimal allowlisted patch and generates from it. |
| `resend-last` | `--say`, `--channel`, `--foreground` | Sends the exact `continuity.last_image`; does not generate or increment revision. |
| `doctor` | none | Reports Python, workflow, state, write access, Hermes, launcher, and ComfyUI checks. |
| `jobs` | `--last N` | Lists recent job JSON records. |
| `job-status` | `JOB_ID` | Returns one job record. |
| `wait` | `JOB_ID`, `--timeout N` | Polls until terminal state or timeout. |
| `backup` | `--output PATH` | Creates a tar.gz containing state/history/local config/workflow. |
| `_worker` | `--job PATH` | Internal background worker entry point; retained for compatibility. |

Queued `show`, `render`, and `resend-last` return JSON containing the job id,
`queued`, deduplication information, and `agent_action: "stop_silently"`.
Foreground calls return the completed job result. Job records transition through
`queued`, `running`, and one of `completed`, `pending_delivery`, or `failed`.

## State and mutation

Schema v1 has top-level `schema_version`, `character`, `visual`, `internal`,
`continuity`, and `memory`. The configured update allowlist is the only writable
surface for `--set`. `update` commits immediately; `render` defers candidate
commit until generation succeeds. `--remember` appends memory without replacing
unrelated state. Writes use a temporary file plus atomic replacement.

`continuity.revision` is monotonically incremented for committed updates and
successful generations. `continuity.last_image`, `last_prompt_id`,
`last_generated_at`, and `last_job_id` are committed together after a valid
image is downloaded. A generation failure leaves the original state and
revision unchanged and does not append a successful generation event.

## Prompt and workflow

`serialize_visual_prompt()` deterministically serializes only current visual
fields in this order: appearance, outfit, legwear, footwear, hair, makeup,
expression, pose, action, scene, lighting, camera. Persona, full history, and
memory text are not added to the ComfyUI dynamic prompt.

The production workflow raw SHA-256 is
`6e5c6b879168e31ceb9af04fd6ffa4d4412618398699e415681b7d45a43a5f3d`.
After replacing only node `63.inputs.value` and node `85.inputs.seed` with their
configured mask values, the canonical JSON SHA-256 is
`279d35360af5a1d5ed402cf11855732237b199130aeba1741d5483ce6db17208`.
The candidate prompt is injected only at node 63 `inputs.value`; a random seed is
injected only at node 85 `inputs.seed`. Node 79 is the configured save node.
The workflow's fixed prompts, including the production-only POV wording, remain
unchanged.

## Queueing, commit, and delivery

Generation follows:

1. Read current state and job request.
2. Under `avatar.lock`, reject a stale base revision and build/validate candidate.
3. Validate the masked workflow hash, inject prompt and seed, submit to ComfyUI,
   poll history, and download a validated image.
4. Atomically store the image, commit candidate state, and append history.
5. Release the generation lock.
6. If enabled, send text first and then a separate
   `MEDIA:/absolute/path/image` Hermes message.
7. Mark the job completed, or preserve a pending-delivery record if delivery
   fails.

Deduplication fingerprints the action, patch, text, memory, channel, and
no-send setting. An equivalent queued/running job is reused; a recently
completed equivalent job is also reused during the configured window. Job
creation itself is not globally locked in v0.2.3.

Text and media are deliberately separate Hermes sends. Media success determines
overall delivery success. Failed delivery never regenerates the image:
`pending_delivery` preserves the exact image and payload, and `resend-last`
uses the state-pinned image rather than scanning the output directory.

## Compatibility requirements

All commands and flags above, JSON/exit-code behavior, allowlist validation,
deterministic prompt serialization, workflow injection points, asynchronous
queueing, current deduplication, transactional generation commit, text-before-
media order, and pending-delivery behavior are protected v0.2.3 contracts.
